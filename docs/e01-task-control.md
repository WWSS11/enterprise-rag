# E01 异步任务取消、重试与失败重放

## 状态与安全边界

文档任务和评测运行新增 `cancelled` 终态。取消只接受尚未被 Worker 领取的 `queued` 状态；
`running` 状态返回 HTTP 409，不使用 Celery `terminate` 强杀进程，避免在 PostgreSQL 与 Milvus
之间留下半发布数据。

取消先在 PostgreSQL 中通过行锁把权威状态写为 `cancelled`，再向 Celery 广播非强制 revoke。
即使广播失败，Worker 在真正执行前仍会读取数据库状态并跳过已取消任务。文档状态会恢复为
`ready`（已有索引）或 `pending`（尚无索引）。

## 可重试范围

以下失败或已取消工作支持 `POST .../retry`：

- 文档入库和重新入库；重新校验源文件存在性后创建新任务。
- 文档删除；文档仍存在时创建新的异步删除任务。
- 本地目录扫描；复用原任务保存的知识库和扫描根别名。
- 全量向量索引重建；仍要求当前租户管理员，并遵守全局单任务约束。
- 评测运行；复用原运行配置快照。若当前 RAG 配置已经变化，返回 HTTP 409，要求发起新的
  Candidate，避免把不同配置冒充为同一次失败重放。

原记录不会改写为新任务。新文档任务保存 `retry_of_job_id`，新评测运行保存
`retry_of_run_id`；取消人、取消时间、原任务和新任务 ID 同时进入持久化记录与审计日志。
数据库唯一索引保证同一个来源任务最多只有一个 `queued/running` 重试。

## 权限

- 文档、扫描和知识库范围任务：关联知识库 `editor` 或更高权限。
- 全量向量索引重建：仅租户管理员。
- 评测运行：数据集关联知识库 `editor` 或更高权限。
- 跨租户资源统一返回 404；后端权限检查是最终边界。

## API

```text
POST /api/v1/jobs/{job_id}/cancel
POST /api/v1/jobs/{job_id}/retry
POST /api/v1/evaluations/runs/{run_id}/cancel
POST /api/v1/evaluations/runs/{run_id}/retry
```

取消成功返回更新后的原记录；重试成功返回 HTTP 202 和新记录。状态不允许、源文件丢失、
配置变化或已有活跃重试时返回 HTTP 409。

## 前端行为

任务中心对排队任务显示“取消排队任务”，对失败或已取消任务显示“重试任务”，并展示来源任务
ID、取消操作者和后端失败原因。评测运行详情提供同样操作；创建评测重试后跳转到新运行详情。
运行中页面明确说明不支持强制终止。
