# E03 飞书连接器管理与手动同步

## 完成范围

E03 为已有飞书 Wiki 增量同步能力增加了管理员控制面：

- 查看连接器是否启用，以及 App ID、App Secret、Wiki 空间、目标知识库和运行身份是否就绪。
- 运行一次只读诊断，验证租户访问令牌和 Wiki 空间首批节点读取能力。
- 手动创建服务端持久化的 `feishu_sync` 任务，并在页面和任务中心持续查看状态。
- 查看远端文档数、待入库、无变化、占用、待删除、不支持节点和子任务数量。
- 查看经过清理的失败分类、飞书错误码、`x-tt-logid`、失败操作和可重试标志。

管理入口为 `/app/connectors/feishu`。导航仅向管理员显示，后端仍执行管理员角色和绑定租户的最终校验；前端隐藏入口不是安全边界。

## API

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| `GET` | `/api/v1/connectors/feishu` | 返回安全配置摘要、就绪检查、活跃任务和最近任务 |
| `POST` | `/api/v1/connectors/feishu/diagnose` | 执行配置及飞书只读连通性诊断并记录审计 |
| `POST` | `/api/v1/connectors/feishu/sync` | 创建持久化手动同步父任务并派发 Worker |

响应不会返回 App ID 或 App Secret 的值，只返回 `app_id_configured` 和 `app_secret_configured`。App Secret 在后端配置对象中使用密文类型，异常和日志不得展开该值。

## 同步与并发边界

手动同步先创建 `queued` 父任务，再由 Worker 原子认领为 `running`。同一租户只允许一个排队中或运行中的 `feishu_sync` 任务，API 前置检查、数据库部分唯一索引和 Redis 连接器锁共同处理重复请求与并发竞态。

同步成功后父任务保存真实统计并进入 `succeeded`；配置、调度、锁冲突或飞书上游失败会进入 `failed` 并保存结构化失败信息。排队任务可从任务中心取消，失败或已取消任务可在当前配置仍有效时重试。已运行任务不做强制终止，以保护文档和索引一致性。

Wiki 节点按最多 50 条分页读取。权限过滤可能导致某一页无节点但仍有下一页，同步会继续读取；缺失或重复游标会终止并报告错误，避免无限循环。当前支持文档类型继续由既有连接器规则决定，不支持节点计入统计而不会伪装成已入库。

## 诊断与排障

诊断依次检查：

1. 连接器开关。
2. 应用凭据是否配置。
3. Wiki 空间是否配置。
4. 目标知识库是否存在、处于活动状态，且运行身份具有编辑权限。
5. 飞书租户令牌和 Wiki 节点只读连通性。

飞书返回非零业务错误码或 HTTP/网络错误时，页面展示可安全公开给管理员的字段。排查上游问题时应优先使用 `x-tt-logid` 与失败操作定位，不应把请求凭据、令牌或完整上游响应写入日志。
