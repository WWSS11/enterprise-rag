# E05 评测集生命周期与批量导入

## 完成范围

E05 在现有评测用例增删改和运行能力之上补齐数据集维护闭环：

- editor 可修改评测集名称和描述，知识库绑定关系保持不可变。
- editor 可复制数据集及其全部用例，副本独立编辑，不复制历史运行、结果或质量门禁记录。
- editor 可归档数据集；归档数据集进入独立状态筛选，历史用例、运行和报告仍可读取，但不能再修改用例、批量导入或发起新运行。
- editor 可选择不超过 2 MB 的 JSON 文件或粘贴 JSON，一次预校验并原子导入最多 500 条用例。

归档不是删除。数据集、用例、运行、结果和报告继续保存在现有表中，不改变历史评测事实。

## API

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| `PATCH` | `/api/v1/evaluations/datasets/{dataset_id}` | 修改名称和描述 |
| `POST` | `/api/v1/evaluations/datasets/{dataset_id}/copy` | 创建数据集及全部用例的独立副本 |
| `POST` | `/api/v1/evaluations/datasets/{dataset_id}/archive` | 将活动数据集归档 |
| `GET` | `/api/v1/evaluations/datasets?status=active|archived|all` | 按生命周期状态查询可访问数据集 |
| `POST` | `/api/v1/evaluations/datasets/{dataset_id}/cases/bulk` | 整批校验并写入 1～500 条用例 |

写操作要求关联知识库 editor 权限并执行租户校验。归档数据集只允许 reader 级历史读取；修改、复制、用例变更、重试或新运行仍要求活动状态。

## 并发与历史一致性

修改、归档、单条或批量用例变更以及发起评测运行会锁定同一数据集行。这样归档与批量导入、用例修改或创建运行不会交错：先取得锁的事务完成后，后续事务会基于最新状态重新判断。

存在 `queued` 或 `running` 运行时，归档返回 409。复制读取源数据集的当前用例并在同一事务中创建副本；唯一名称冲突返回 409，任何失败都会回滚整个副本，不留下部分用例。

归档后，运行详情、报告、对比和门禁通过允许归档读取的授权路径继续可用。归档数据集本身不再参与默认活动列表，也不能启动或重试运行，从而同时满足历史可追溯和状态冻结。

## 批量导入格式

界面接受用例数组或带 `cases` 字段的对象：

```json
{
  "cases": [
    {
      "question": "访问受限资料需要什么审批？",
      "reference_answer": "需要知识库负责人审批。",
      "expected_document_ids": ["00000000-0000-4000-8000-000000000001"],
      "required_key_points": ["负责人审批"],
      "tags": ["访问控制"]
    },
    {
      "question": "资料中没有的管理员密码是什么？",
      "reference_answer": "现有资料不足，应该拒答。",
      "should_refuse": true,
      "tags": ["拒答"]
    }
  ]
}
```

文档字段必须使用当前知识库内状态为 `ready` 的文档 UUID。浏览器先检查 JSON 结构、UUID、字段长度、可回答题的预期文档、拒答题文档约束和关键点组锚点，再显示可回答题/拒答题计数。后端使用同一既有业务规则重新校验文档归属和题目约束，并在一个事务中写入全部用例；任一用例无效时不会部分导入。
