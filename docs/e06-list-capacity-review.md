# E06 非关键列表容量复核

## 决策

E06 完成证据复核，但不新增列表分页或搜索实现。

T15 已把所有集合接口从无界响应收紧为显式上限；当前实测规模、延迟和错误率均未达到继续改造的触发条件。此时为低数据量页面加入更多分页状态、总数查询或专用搜索索引，会增加前后端复杂度，但没有可测量收益。

本结论只适用于当前已验证规模，不表示列表永远不需要继续扩展。

## T15 证据

T15 隔离环境中的活动数据为：

| 数据 | 数量 |
| --- | ---: |
| 知识库 | 3 |
| 文档 | 20 |
| 成员关系 | 10 |
| 会话 | 13 |
| 评测集 | 2 |
| 审计记录 | 100 |

六类鉴权控制面读取各执行 50 次、并发 10，错误率均为 0。P95 为 23.458～55.271 ms，没有出现响应时间、内存、返回体或数据库查询瓶颈。T15 明确把“单租户知识库、成员或评测集超过 1000 条”定义为继续增加总数、游标或专用搜索索引的复测条件；当前数据距离该阈值较远。

## 接口与界面盘点

| 列表 | 服务端边界 | 当前界面 | E06 决策 |
| --- | --- | --- | --- |
| 知识库 | `q + limit + offset`，最多 100 | 首批列表和选择器 | 当前仅 3 条，延期界面分页 |
| 文档 | `q + limit + offset`，最多 100 | 按知识库显示首批文档 | 当前共 20 份，延期界面分页 |
| 知识库成员 | `q + limit + offset`，最多 100 | owner 查看首批成员 | 当前 10 条，延期界面分页 |
| 评测集 | `q + status + limit + offset`，最多 100 | 活动/归档状态筛选 | 当前 2 条，延期搜索和分页 |
| 任务 | 分页响应含 `total`，最多 100 | 已有状态、类型、知识库筛选和翻页 | 已完成，无需修改 |
| 会话 | 分页响应含 `total`，最多 100 | 每个知识库/状态读取最近 50 条 | 当前 13 条，延期会话选择器分页 |
| 会话消息 | 分页响应含 `total/has_more`，最多 200 | 每次加载最近/更早 50 条 | 已完成，无需修改 |
| 审计日志 | 分页响应含 `total`，最多 100 | 已有字段筛选和翻页 | 已完成，无需修改 |
| 评测用例 | `q + type + total + limit + offset`，最多 100 | 已有搜索、题型筛选和翻页 | 已完成，无需修改 |
| 评测运行 | 状态筛选、`total + limit + offset`，最多 100 | 已有状态筛选和翻页 | 已完成，无需修改 |

内部权限过滤调用不会套用面向页面的 100 条上限：`list_accessible_identity` 默认 `limit=None`。因此任务、会话、文档和评测的跨知识库授权过滤不会因为页面分页而只检查前 100 个知识库。

## 后续触发条件

出现以下任一条件时重新打开列表容量任务，并在相同数据规模下复测前后版本：

1. 单租户知识库、成员或评测集达到或预计达到 1000 条。
2. 用户需要的实体因为首批 100 条截断而无法在列表或选择器中找到。
3. 控制面列表 P95、返回体或数据库资源使用出现有证据的增长问题。
4. 真实首批内部业务规模与 T15 样本存在数量级差异。

重新实施时应优先为确有问题的资源增加分页响应总数或稳定游标、前端搜索和翻页；只有查询计划或压测证明普通索引搜索不足时才增加专用搜索索引。不得一次性改造所有列表。

## 自动验证

`tests/test_control_plane_history.py::test_e06_collection_limits_remain_bounded_in_openapi` 固化了十类集合接口的默认值、最大页大小、非负 offset，以及需要 `q` 的资源。它防止后续改动无意中恢复无界响应。

复核验证结果：Ruff、mypy、pip check 和后端全量 167 条 pytest 通过，其中控制面历史与 T15 负载探针相关测试共 13 条；OpenAPI 盘点确认所有集合接口仍有显式上限。本任务没有数据库迁移、前端行为变化或部署配置变更。
