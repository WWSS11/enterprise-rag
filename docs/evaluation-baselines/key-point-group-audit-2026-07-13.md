# 关键点同义组双指标审计

日期：2026-07-13

## 目标

原 `key_point_coverage` 使用确定性字面包含匹配，适合作为稳定、可复现的严格指标，但会把自然语言与代码中的等价表达记为未命中。例如答案出现 `worker_prefetch_multiplier=1` 时，严格标注“预取一个”不会命中。

本次没有修改或覆盖严格指标，而是新增独立的 `key_point_group_coverage`：每个关键点组可以保存多个经过人工审计的等价表述，答案命中组内任意一个别名即视为该组命中。

## 数据与实现

- PostgreSQL 为 `evaluation_cases` 新增 `required_key_point_groups` JSON 字段。
- 迁移将所有历史严格关键点回填为单元素组，保证旧数据行为兼容。
- API 创建、读取和报告模型均返回同义组标注。
- `key_point_coverage` 与 `matched_key_points` 保持原算法不变。
- 新增 `key_point_group_coverage` 与 `matched_key_point_groups`。
- 源码 holdout v1 人工审计 9 条用例，共加入 29 个包含多个别名的关键点组。
- 本次仅使用已经持久化的答案、检索、重排和引用结果回算，没有调用 Chat、Embedding 或 Rerank 模型。

## 四个运行的回算结果

| 运行 | 严格覆盖率 | 同义组覆盖率 | 差值 |
| --- | ---: | ---: | ---: |
| 源码 Control `b809d964-509f-4a0a-a204-2d91420d301e` | 0.785833 | 0.915833 | +0.130000 |

| Score-aware diversity `6b2e4f43-c583-4a45-a611-cd2d13880129` | 0.795833 | 0.915833 | +0.120000 |

项目架构回归集没有专门扩展同义组，因此新指标与严格指标一致。这证明新字段对未审计数据保持兼容，不会自动抬高所有运行分数。

## Score-aware 运行中的典型差异

| 用例 | 严格 | 同义组 | 被识别的等价表达示例 |
| --- | ---: | ---: | --- |
| 语义断点候选与数量限制 | 0.60 | 1.00 | `source_section_index`、配置字段名与自然语言参数说明 |
| LangGraph 查询改写条件 | 0.50 | 1.00 | “对话历史”/`history`、`ANAPHORA_MARKERS`、`rewrite_query` |

## 结论与边界

当前源码 Score-aware 基线应同时报告：严格关键点覆盖率 `0.795833`，人工审计同义组覆盖率 `0.915833`。前者适合观察不变标尺下的长期趋势，后者更接近人工判断的语义覆盖，但仍然只是确定性字符串匹配，不等同于完整的答案正确性或忠实度评判。

新增别名必须经过评测集审计，不能根据某次模型答案临时放宽；否则会产生对历史输出过拟合。后续如引入 LLM-as-Judge，应继续作为第三个独立指标保存，而不是替换这两个确定性指标。
