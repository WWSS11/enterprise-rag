# 拒答检测首结论句重算

日期：2026-07-13

## 问题

原确定性拒答检测读取答案第一个段落的前 180 个规范化字符。源码 holdout 中的问题“拒答检测为什么只检查答案开头，并检查多长的规范化文本？”被模型正常回答，但答案为了说明实现而在开头段落提到“无法回答”“不知道”等拒答标记，评测器将其误判成模型拒答。

这属于评测器元问题误判，不是 RAG 生成失败。

## 规则调整

新规则只检查答案的第一结论句：

1. 以第一个中文或英文句末标点为边界。
2. 移除该句中的 Markdown inline code、中文引号和单双引号内容。
3. 对剩余文本做 NFKC、casefold 和符号清理。
4. 只在前 120 个规范化字符中查找拒答标记。

因此以下内容不会被误判：

```text
拒答检测只检查答案开头，是为了避免把后文误判为拒答。
例如系统会识别“无法回答”和 `不知道` 等标记。
```

真实拒答仍然能够识别：

```text
根据当前资料，我无法回答客户订单数量。
```

## 结论

新规则减少了“讨论拒答机制”与“模型正在拒答”之间的混淆，同时保留显式首句拒答识别。该指标仍是确定性启发式，而不是完整的语义裁判；后续如果增加 LLM-as-Judge，应作为独立指标保存，不能覆盖当前可重复的规则结果。
